# SME01 — Driven_Oscillator_Resonance

**Status:** draft, pending SME sign-off  
**Domain:** Physics → Computational Physics  

## 1. What the task is about

An undamped harmonic oscillator with natural frequency ω₀ = 1 starts from rest and is driven by a 2π-periodic force:

    y''(t) + y(t) = μ(t),    y(0) = y'(0) = 0

The physics question: **when does the oscillator settle into a periodic motion, and when does it resonate and grow without bound?** The answer (exam question I.4.4) is that the response is 2π-periodic if and only if the forcing has no component at the natural frequency, i.e. its first Fourier coefficients a1 and b1 are both zero. Otherwise the amplitude grows linearly in time.

The model only receives the force as **N samples** on a uniform grid t_j = 2πj/N (N odd). The task defines μ as the trigonometric interpolant of those samples. Every expected answer is therefore exact, and no discretization error is tolerated.

## 2. What the model must write

| Step | Function | What it must do |
|---|---|---|
| SME01.1 | `forcing_resonant_modes(mu)` → `[a1, b1]` | Extract the component of the force at the natural frequency |
| SME01.2 | `periodic_response(mu, tol)` → array or `None` | Return `None` if the force resonates (√(a1² + b1²) > tol). Otherwise return the periodic response on the grid, with y(0) = y'(0) = 0 |
| SME01.3 | `driven_response(mu, t)` → array | Return the exact response at any times t, including the linear growth at resonance |
| general test | step 2 feeding step 3 | The periodic response φ to \|sin t\| is used as a new forcing. It resonates (a1(φ) = −π/4), so the response grows without bound (exam question III.5) |

The exact prompts, function headers and test code are in `problem.json` (SciCode format). The expected values are in `test_data.h5`, and the reference (gold) solution is in `gold/`.

**What makes it hard:** the solver has to handle a **singular mode**. In Fourier space each mode obeys (1 − k²)·y_k = c_k, and for k = ±1 that reads 0·y = c. A naive solver divides by zero or by a tiny number. A correct one must detect the resonance and switch to the secular solution (t/2)(a1 sin t − b1 cos t).

## 3. Errors and why they matter

### 3a. Errors the hidden tests catch

Each error below is a plausible mistake. Each one fails at least one hidden test, while the gold solution passes them all (checked by `validate.py`). This shows that a failure means a real scientific or coding error, not an ambiguity in the task.

| Error | Tests failed | Why it matters |
|---|---|---|
| 1/N instead of 2/N normalization | 3/3 (step 1) | The forcing amplitude is off by a factor of 2, so every downstream response is wrong |
| Sign of b1 flipped (FFT convention) | 1/3 (step 1) | numpy's FFT uses e^{−ikt}, so b1 = −2·Im(c1), not +2·Im(c1). Getting it wrong flips the phase of the resonant forcing |
| Forgets y'(0) = 0 (no sin t correction) | 1/3 (step 2) | The result is a solution of the ODE, but not the one that starts from rest |
| Returns only the periodic particular solution | 2/3 (step 2) | It ignores the initial conditions entirely, which is the classic confusion between "a solution" and "the solution of the Cauchy problem" |
| Regularized division instead of the secular term | 3/3 (step 3) | Dividing by (1 − k² + ε) hides the resonance. Physically, this misses the defining behaviour of a resonant oscillator, the linear growth of its amplitude |
| Float wave numbers from `np.fft.fftfreq(N, 1/N)` | 1/3 (step 3, N = 49) | A common numpy idiom. For some N it returns 1.0000000000000002, so `k == 1` fails and the code divides by about 1e−16. This is a genuine floating-point trap in resonance detection |
| Forgets y_s'(0) = −b1/2 in the initial slope | 1/3 (step 3) | The secular term has a non-zero slope at t = 0. Without the correction, the solution no longer starts from rest |

### 3b. Errors found while building the task

| What happened | Why it matters |
|---|---|
| **Bug in the first gold solution.** It used `np.fft.fftfreq(N, d=1/N)`. For 134 odd N below 2000 (for example 49, 103 and 1601), the "1" comes out as 1.0000000000000002, so the resonant mode was divided by about 1e−16. The first hidden tests (N = 33, 65, 101) **did not catch it**. The independent check of the exam's III.5 growth rate did. Fixed with integer wave numbers, and a hidden test at N = 49 now covers it. | This shows why the gold solution must be checked against **independent** oracles and not only against its own targets (deck, slide 8: "Independent oracle"). Targets generated by a buggy gold solution would have graded correct code as wrong. That is the same defect we found in SciCode task 9.1 (Weighted Jacobi), whose stored answers come from an iteration that drops the (1 − ω)·x term. |
| **Aliasing of \|sin t\|.** On an odd grid, the even harmonics cos((N ± 1)t) fold onto k = 1, so the sampled \|sin t\| has a1 ≈ −3.1e−4 at N = 101, even though the continuous function has a1 = 0. The step 2 test therefore uses tol = 1e−3. | Without this, the exam's flagship example would be classified as resonant and the test would be unfair. The tolerance must reflect realistic numerical behaviour (deck, slide 8: "Tolerances"). |
| **Typos in the official worked solution.** In I.4.3, "F(x + π) − F(x)" should read F(x + 2π) − F(x). In the remark after I.3, the integrands should be μ(t) cos t and μ(t) sin t. | No impact on the task: the validation uses the correct formula from I.1. Source material must be checked too, not copied blindly. |

## 4. Why the gold solution is correct

`validate.py` compares the gold solution (Fourier/FFT method) with sources that share none of its code:

1. **Closed forms.** [1, 0] and [2 sin 0.3, 2 cos 0.3] for step 1, a hand-derived φ for step 2, and (t/2) sin t for step 3. Agreement is about 1e−14.
2. **Direct ODE integration.** scipy DOP853 at rtol 1e−12, with the forcing evaluated by explicit cos/sin sums. Agreement is about 3e−10 over 40π.
3. **Variation of constants, from the official worked solution (I.1–I.3).** φ(x) = sin x·G(x) − cos x·H(x), with G and H integrated exactly. Agreement is about 1e−15 on every case, including resonance. The closed forms φ_sin = (sin x − x cos x)/2 and φ_cos = x sin x/2 (I.4.6) are also reproduced.
4. **Exam results.** a_2p(|sin|) (III.2.1), a_2p(φ) (III.3.3), a1(φ) = −π/4 (III.3.4), the sum in III.4, ∫₀^∞ e^{−t}φ dt = coth(π/2)/4 (II.3.2), and growth at (π/8)·t (III.5) are all reproduced.

**Tolerances:** the default `np.allclose` (rtol 1e−5, atol 1e−8). The gold solution is accurate to about 1e−12, which leaves a wide margin for other correct methods, such as explicit DFT sums or the variation-of-constants formula.

## 5. Points for the SME reviewer

1. Is the "interpolant of the samples" convention clear enough that a solver won't compute continuum Fourier coefficients instead?
2. Is tol = 1e−3 for the aliased |sin t| case acceptable?
3. Does the step 2 prompt ("remove the cos t and sin t modes") leave room for a different but valid reading?
4. Should the task be retagged under Mathematics → Numerical Linear Algebra (circulant operator, singular system)?
